# 논문 QA 슬랙 봇

> 슬랙에 논문 PDF를 올리면 봇이 읽어 두고, `@봇 질문`으로 물으면 논문 내용을 근거로 **쪽 번호와 함께** 답해 주는 로컬 RAG 봇

## 1. 목적

논문을 읽다 보면 "이 실험의 평가 지표가 뭐였지?", "저자들이 말한 한계가 어디에 있었지?" 같은 질문이 계속 생기는데, 그때마다 PDF를 다시 열어 해당 부분을 찾아야 해서 흐름이 끊긴다. 팀이 쓰는 슬랙에 논문을 올려 두고 그 자리에서 물으면, 논문 속 근거를 찾아 출처(논문명, 쪽)와 함께 답해 주도록 하여 논문 확인에 드는 시간을 줄인다. 논문 파일이 외부 서비스로 나가지 않도록 모든 처리는 내 PC에서 로컬로 실행한다.

## 2. 기능

- **논문 업로드 인식**: 봇이 들어가 있는 채널에 PDF를 올리면 자동으로 내려받아 인덱싱하고, 완료되면 같은 스레드에 "N쪽, M개 조각으로 저장했습니다"라고 알린다.
- **논문 근거 질의응답**: `@봇 질문`으로 물으면 올려 둔 논문에서 관련 부분을 찾아 그 내용만으로 답하고, 같은 스레드에 답을 단다.
- **출처 표기**: 답변 끝에 근거로 쓴 부분의 `[논문 제목, p.쪽번호]`를 붙인다.
- **모르면 모른다고 답함**: 검색된 내용에 답이 없으면 지어내지 않고 "올려 주신 논문에서 해당 내용을 찾지 못했습니다"라고 답한다.
- **한국어 질문, 영어·한국어 논문**: 질문은 한국어로 하고, 논문은 영어든 한국어든 읽을 수 있다. 답변은 한국어로 한다.
- **채널 단위 논문 보관**: 한 채널에 최대 5편까지 올려 둘 수 있고, 그 채널에서 한 질문은 그 채널의 논문에서만 검색한다.

## 3. 사용 모델과 선택 근거

- 생성 모델: `gemma3:4b` (Ollama)
- 임베딩 모델: `qwen3-embedding:0.6b` (Ollama)
- 근거:
  - **로컬 실행·보안**: 아직 공개되지 않은 논문이나 팀 내부 자료가 외부 API로 나가지 않아야 해서 상용 API를 쓰지 않는다.
  - **VRAM**: 아래 계산처럼 생성 모델과 임베딩 모델을 동시에 올려도 8GB 안에 들어온다.
  - **한국어 질문 + 영어 논문**: 임베딩 모델이 다국어를 지원해야 한국어 질문으로 영어 논문 조각을 찾을 수 있다. (슬라이드 21번 "한국어 지원" 기준)
  - 4주차 비교표에서 위 근거에 해당하는 항목명은 제출 전에 표의 표현에 맞춰 고칠 것. **(확인 필요)**
- VRAM 계산 (추정치. 모델 크기 + KV 1.5GB 가정, 슬라이드 22번 방식):

  | 항목 | 크기 |
  |---|---|
  | `gemma3:4b` | 약 3.3GB |
  | `qwen3-embedding:0.6b` | 약 0.6GB |
  | KV 캐시(가정) | 1.5GB |
  | **합계** | **약 5.4GB → 8GB 안에 들어감** ✅ |

  - 모델 크기는 Ollama 라이브러리 표기 기준의 기억값이라 제출 전에 `ollama list`로 실제 크기를 확인한다. **(확인 필요)**
  - 14주차에 실행하며 `ollama ps`와 `nvidia-smi`로 실측값을 적는다.
  - 개인 노트북 GPU(RTX 4050)의 VRAM이 6GB일 수 있으므로 `nvidia-smi`로 실제 용량도 함께 확인한다. 합계 5.4GB는 6GB에도 들어가지만 여유가 작다. **(확인 필요)**

## 4. 사용 스택

- **LangChain**
  - 문서 적재·분할: `PyPDFLoader`(쪽 번호를 메타데이터로 보관), `RecursiveCharacterTextSplitter`
  - 모델: `ChatOllama`(생성), `OllamaEmbeddings`(임베딩)
  - 검색: 로컬 벡터 저장소(Chroma 예정)의 retriever + **메타데이터 필터**(채널 단위 검색)
  - 답변 생성: `ChatPromptTemplate` + 출력 파서로 구성한 RAG 체인
- **LangSmith** ★ 필수
  - 질문 처리 체인 전체(검색 → 프롬프트 → 생성)를 추적해서, 어떤 조각이 검색되었고 어떤 프롬프트로 답이 나왔는지 확인한다.
  - 논문 인덱싱 단계(적재 → 분할 → 임베딩)도 추적해서 조각 수와 처리 시간을 확인한다.
  - 추적에 `channel_id`, `paper_id`를 태그로 붙여 질문별로 구분한다.
  - 14주차 제출물로 추적 캡처를 첨부한다.
- **LangGraph**: 사용하지 않는다. (검색 → 생성으로 이어지는 단일 흐름이라 필요하지 않다.)
- **슬랙 연동**: `slack_bolt` + Socket Mode (9주차 `slack_llm_bot.py` 기반). 파일 업로드 인식을 위해 `file_shared` 이벤트 구독과 `files:read` 권한을 추가한다.

## 5. 실행 방법

> 구현 전 명세 단계의 계획이다. 14주차 제출 시 실제 동작 기준으로 갱신한다.

1. 모델 준비
   ```bash
   ollama pull gemma3:4b
   ollama pull qwen3-embedding:0.6b
   ```
2. 패키지 설치
   ```bash
   python -m venv .venv
   source .venv/Scripts/activate   # Windows git bash 기준
   pip install -r requirements.txt
   ```
3. 루트 `.env` 작성 (코드나 커밋에 넣지 않는다)
   ```
   SLACK_BOT_TOKEN=xoxb-...
   SLACK_APP_TOKEN=xapp-...
   LANGSMITH_TRACING=true
   LANGSMITH_API_KEY=...
   LANGSMITH_PROJECT=paper-qa-bot
   ```
4. 슬랙 앱 설정 (9주차 앱에 추가)
   - Bot Token Scopes: `app_mentions:read`, `chat:write`, `files:read`
   - Event Subscriptions(Socket Mode): `app_mention`, `file_shared`
   - 권한을 바꾼 뒤에는 워크스페이스에 앱을 다시 설치하고, 봇을 사용할 채널에 초대한다.
5. 실행
   ```bash
   python app.py
   ```
6. 사용
   - 채널에 논문 PDF를 올리고 "저장했습니다" 알림이 오면 `@봇 이 논문의 평가 지표는 뭐야?`처럼 질문한다.
